     3 ОПИС ВИКОНАНОЇ РОБОТИ
     Розроблено сучасну корпоративну екосистему Eco Office, призначену для автоматизованого моніторингу життєдіяльності офісних рослин, контролю мікроклімату та координації сервісного персоналу. Метою проєкту є вирішення проблеми нераціонального догляду за озелененням шляхом збору IoT-телеметрії (вологість ґрунту, температура, освітлення) та інтелектуального розподілу робочих завдань. Апаратна частина базується на енергоефективних мікроконтролерах ESP32, тоді як програмна інфраструктура складається з масштабованого бекенду та швидкого клієнтського Single Page Application (SPA).
     2. Архітектура серверної частини та масштабованість Для гарантування стабільної обробки безперервного потоку даних від IoT-пристроїв та користувачів було впроваджено парадигму горизонтального масштабування (Horizontal Scaling). Це дозволило нівелювати обмеження однопотокового циклу подій (Event Loop) у середовищі Node.js, зокрема під час ресурсомістких операцій хешування паролів.
     • Контейнеризація та оркестрація: Програмний код бекенду запаковано в ізольовані Docker-образи (stateless-архітектура). Управління життєвим циклом контейнерів здійснюється через Kubernetes (K8s). За допомогою об'єкта Deployment забезпечується підтримка цільової кількості реплік та висока доступність (High Availability).
     • Балансування навантаження: Для диспетчеризації вхідних підключень налаштовано Kubernetes Service (LoadBalancer), який розподіляє трафік між подами за принципом Round-Robin.
     • Управління даними: Консистентність даних гарантується використанням єдиної централізованої реляційної СУБД PostgreSQL у зв'язці з Drizzle ORM.
     • Навантажувальне тестування: За допомогою інструмента Locust проведено стрес-тестування системи. Завдяки налаштованому автоскейлінгу (Horizontal Pod Autoscaler) кластер успішно обробив імітацію сотень одночасних підключень без деградації часу відповіді (Response Time) та без обривів з'єднань.
     3. Проєктування клієнтського додатка (Frontend) Клієнтську частину побудовано на базі бібліотеки React.js із застосуванням інструменту збірки Vite. Використання нативних ES-модулів забезпечило високу швидкість завантаження додатку та оптимізацію кінцевого JavaScript-коду.
     • Управління станом: Стан додатку децентралізовано за допомогою реактивної бібліотеки Zustand. Створено ізольовані сховища (наприклад, useAuthStore для сесій), що дозволило уникнути надлишкового ререндеру компонентів та підвищити продуктивність на бюджетних мобільних пристроях персоналу.
     • Візуальне оформлення: Інтерфейс розроблено за допомогою фреймворку Tailwind CSS (за підходом utility-first). Завдяки JIT-компілятору згенеровано мінімальний за обсягом CSS-файл, повністю адаптований під різні роздільні здатності екранів.
     • Маршрутизація та безпека: Навігацію реалізовано через React Router v6. Впроваджено HOC-патерни для захисту конфіденційної інформації та суворого розмежування доступу залежно від ролі користувача (CLEANER, FLORIST, OFFICE_MANAGER).
     4. Мережева взаємодія та робота з IoT-даними Для безпечного обміну даними між клієнтом та сервером розроблено ізольований сервісний шар на базі Axios.
     • Перехоплювачі (Interceptors): Налаштовано автоматичну ін'єкцію JWT-токенів у заголовки запитів (Authorization) та глобальну обробку помилок 401 Unauthorized, що забезпечує автоматичне скидання недійсних сесій.
     • Оптимізація IoT-синхронізації: З огляду на використання сенсорами режиму глибокого сну (Deep Sleep) для збереження заряду батарей, було визнано недоцільним використання постійних WebSocket-з'єднань. Натомість впроваджено підхід On-Demand Pull (ручне та інтервальне оновлення даних), що суттєво економить трафік та ресурси сервера.
     • Оптимістичний інтерфейс (Optimistic UI): Для усунення затримок під час роботи лінійного персоналу реалізовано алгоритм оптимістичного оновлення. При виконанні завдання інтерфейс реагує миттєво, а синхронізація статусу та запис у журнал догляду (Care Log) відбуваються у фоновому асинхронному режимі. Передбачено механізм автоматичного відкату (rollback) у разі помилки мережі.

     

     
     
     
     
     
     
     
     
     
     

4 ВИСНОВКИ
     У результаті виконання проєкту розроблено надійну, масштабовану та високопродуктивну програмну інфраструктуру Eco Office. Використання мікросервісних підходів (Docker, Kubernetes) забезпечило стійкість бекенду до пікових навантажень. Впровадження сучасного фронтенд-стеку (React, Vite, Zustand) та архітектурних патернів (Optimistic UI) дозволило створити зручний, безвідмовний інструмент для автоматизації догляду за офісними екосистемами, що повністю відповідає поставленим технічним та бізнес-вимогам.
