     3 ОПИС ВИКОНАНОЇ РОБОТИ
       
     Eco Office - це сучасна корпоративна екосистема, розроблена для моніторингу життєдіяльності офісних рослин, контролю мікроклімату робочих кабінетів та координації сервісного персоналу (клінерів та флористів). Головне завдання платформи - забезпечення автоматизованого догляду за озелененням офісу, запобігання загибелі рослин від посухи чи неналежного освітлення за допомогою аналізу IoT-телеметрії, а також інтелектуальний розподіл робочих завдань на зміну.
     Апаратна частина системи складається з бездротових сенсорних вузлів на базі мікроконтролерів ESP32, обладнаних вологомірами ґрунту, датчиками температури й вологості повітря, люксметрами та контролерами заряду батареї. Серверна частина базується на Node.js, а клієнтський інтерфейс розроблено як швидкий кросплатформовий Single Page Application (SPA).
     Для закладання надійного фундаменту архітектури фронтенд-додатка було використано генеративні моделі ШІ з подальшим глибоким рефакторингом, ручною оптимізацією та адаптацією під реляційну схему даних PostgreSQL.
     Інструмент штучного інтелекту: Google Gemini
     Версія: 1.5 Pro
     Ціль використання ШІ: Генерація початкової модульної структури проекту, налаштування глобальних роутів, створення захищених зон кабінету та проектування базового REST-клієнта Axios для взаємодії з IoT-сервером.
     Початковий промпт (Prompt): "Design a modern, performance-oriented React SPA for a corporate IoT plant monitoring system called Eco Office. Use Vite, Tailwind CSS, and React Router v6. Split role access for CLEANER, FLORIST, and ADMIN. Implement centralized store management using Zustand for session and local states. Centralize API calls using Axios with automatic JWT interceptors and global 401 session expiration handling. Design clean, intuitive screens: login, workspace dashboard with active task indicators and floor layout map, interactive plant details screen with telemetry meters and maintenance logs, species directory, and user tasks list."
     Внесок автора: Проєктування бізнес-логіки розподілу нарядів (Tasks), розробка UML-моделей даних, інтеграція та адаптація TypeScript-інтерфейсів під реляційну базу даних, рефакторинг та повне винесення коду взаємодії з REST API у сервісний шар (Services), ручне проектування адаптивного мобільного інтерфейсу та впровадження патерна «Optimistic UI» для миттєвого відгуку при виконанні завдань працівниками.
     Клієнтську частину побудовано на базі бібліотеки React.js з використанням сучасного інструменту збірки Vite. На відміну від морально застарілого підходу Create React App на базі Webpack, Vite використовує нативні ES-модулі (ESM) під час розробки. Це рішення забезпечує миттєвий запуск локального середовища розробки (до 300 мс) та надзвичайно швидке оновлення модулів (Hot Module Replacement) без перезавантаження всього стану сторінки. Для фінального складання (Production Build) Vite використовує Rollup, генеруючи легковажний, розділений на чанки та оптимізований JavaScript-код, що позитивно впливає на швидкість завантаження додатку на смартфонах персоналу при роботі через корпоративний Wi-Fi.
     Децентралізоване управління станом додатку (Zustand)
     Згідно з системними діаграмами компонентів, увесь стан додатку повністю ізольовано від візуальної частини (UI) за допомогою реактивної бібліотеки Zustand. Головною інженерною перевагою цього вибору є відсутність необхідності огортати дерево компонентів у складні провайдери (Context Provider), як це реалізовано в Redux чи React Context. Zustand дозволяє створювати незалежні сховища станів:
     • useAuthStore - керує сесією поточного користувача, токеном авторизації та даними його профілю.
     Завдяки підписці на вибіркові поля стану (Selectors), оновлення масиву об'єктів у пам'яті (наприклад, зміна статусу таски або оновлення списку кімнат) викликає ререндер виключно тих React-компонентів, які безпосередньо використовують ці дані. Це гарантує високу швидкість роботи інтерфейсу навіть на бюджетних мобільних пристроях працівників клінінгу.
     3. Візуальне моделювання та адаптивний дизайн (Tailwind CSS)
     Весь графічний інтерфейс побудовано за допомогою фреймворку Tailwind CSS за підходом utility-first. Свідома відмова від важких заздалегідь стилізованих бібліотек компонентів (Material UI, Bootstrap) дозволила створити унікальний брендований дизайн системи Eco Office (комбінація смарагдових, темно-сірих та м'яких пастельних тонів) та забезпечити повний контроль над адаптивністю.
     Завдяки JIT-компілятору (Just-In-Time) Tailwind аналізує код додатку та включає у фінальну таблицю стилів лише ті класи, які дійсно використовуються. Це радикально зменшує розмір CSS-файлу. Використання мобільних префіксів (sm:, md:, lg:) дозволило оптимізувати додаток як для десктопних моніторів офіс-менеджерів, так і для екранів смартфонів клінерів та флористів під час обходу приміщень.
     4. Гнучка система маршрутизації та безпеки (React Router)
     Для навігації додатком використано React Router v6. Структура сторінок побудована навколо системи вкладених маршрутів (<Outlet />). Це дає змогу зафіксувати глобальний скелет інтерфейсу (шапка профілю з онлайн-статусом, бокове меню з розділами "Робочий стіл", "Завдання", "Довідник видів") та динамічно підміняти лише центральну область екрану.
     Для захисту конфіденційної інформації та розмежування ролей реалізовано патерни вищого порядку (HOC):
     • ProtectedRoute - перехоплює спробу переходу за внутрішніми посиланнями, перевіряє стан авторизації в useAuthStore і примусово повертає неавторизованого гостя на сторінку входу.
     • Рольовий фільтр: Робочі процеси суворо диференційовані. Клінери (CLEANER) мають доступ лише до списку завдань та базового дашборду. Можливість редагувати паспорт рослини (змінювати назву, QR-код) та довідник видів рослин (PlantSpecies.tsx) відкривається лише для флористів (FLORIST), офіс-менеджерів (OFFICE_MANAGER) та адміністраторів (ADMIN).
     5. Централізований шар взаємодії з REST API та Axios Interceptors
     Для взаємодії з базою даних розроблено ізольований сервісний шар (src/api/client.ts та src/api/services.ts), який інкапсулює у собі роботу з мережею за допомогою бібліотеки Axios. Для усунення рутинного дублювання логіки автентифікації у кожному запиті налаштовано автоматичні інтерцептори (Interceptors).
     • Request Interceptor: Автоматично вилучає збережений JWT-токен із локальної пам'яті пристрою (localStorage або AsyncStorage) і впроваджує його у заголовок Authorization: Bearer <token> для кожного запиту до бекенду.
     • Response Interceptor: На найнижчому рівні перехоплює помилку 401 Unauthorized (коли термін дії сесії закінчився). Він автоматично скидає глобальний стан авторизації у Zustand, видаляє недійсні ключі з пам'яті пристрою та робить редірект на сторінку логіну, запобігаючи несанкціонованому доступу до даних.
     Реалізація перехоплювачів Axios у системі Eco Office:
      1. apiClient.interceptors.request.use(
      2.   async (config) => {
      3.     const token = localStorage.getItem('eco_office_token');
      4.     if (token && config.headers) {
      5.       config.headers.Authorization = `Bearer ${token}`;
      6.     }
      7.     return config;
      8.   },
      9.   (error) => Promise.reject(error)
      10. );
      11. 
      12. apiClient.interceptors.response.use(
      13.   (response) => response,
      14.   (error) => {
      15.     if (error.response?.status === 401) {
      16.       localStorage.removeItem('eco_office_token');
      17.       localStorage.removeItem('eco_office_user');
      18.       if (window.location.pathname !== '/login') {
      19.         window.location.href = '/login';
      20.       }
      21.     }
      22.     return Promise.reject(error);
      23.   }
      24. );
     
     Оптимістичний інтерфейс (Optimistic UI) для робочих завдань
     Робота лінійного персоналу вимагає швидкої реакції додатку без зависань інтерфейсу під час завантаження запитів. Для забезпечення миттєвого фідбеку під час виконання завдань (наприклад, поливу рослини) реалізовано підхід Optimistic UI.
     Коли працівник натискає кнопку «Виконати» на сторінці завдань:
     1. Клієнтська частина миттєво візуально позначає це завдання як "Виконане" на екрані, а в бічний блок "Журнал операцій" оптимістично додається свіжий лог догляду з поточною міткою часу.
     2. Паралельно у фоновому режимі виконуються два асинхронні запити: PATCH /tasks/:id (переведення завдання в статус COMPLETED) та POST /logs (фіксація операції в базі даних).
     3. Якщо мережа стабільна, завдання фіксується на сервері непомітно для користувача.
     4. У разі виникнення помилки з'єднання, система автоматично робить відкат (Rollback): завдання повертається до списку активних, тимчасовий лог видаляється, а користувач бачить інформаційне сповіщення про збій зв'язку.


     
     4 ВИСНОВКИ
       
     У ході виконання роботи було спроектовано та успішно втілено клієнтську архітектуру IoT-системи Eco Office. Розроблений клієнтський SPA-додаток є високопродуктивним, гнучким та захищеним інструментом для щоденної координації персоналу та збереження здоров'я рослин в офісному просторі.
     Завдяки децентралізації стану за допомогою Zustand, розробці сервісного рівня взаємодії з REST API та інтеграції інтерсепторів Axios, проект позбавлений надлишкового коду та гарантує надійне й безпечне керування сесіями користувачів. Впровадження підходу Optimistic UI дозволило усунути затримки інтерфейсу при фіксації виконаних робіт, що робить мобільний та веб-інтерфейс максимально чуйним та зручним для лінійного персоналу офісу. Платформа Eco Office повністю адаптована під сучасні вимоги до енергоефективності IoT-пристроїв та є готовим рішенням для створення здорового екологічного середовища в офісах.
