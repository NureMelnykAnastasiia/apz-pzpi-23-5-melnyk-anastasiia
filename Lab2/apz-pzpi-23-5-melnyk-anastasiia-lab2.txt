2 ЗАВДАННЯ
     
     Необхідно розробити мобільний програмний застосунок для будь-якої поширеної на сьогодні мобільної платформи. Мобільний застосунок повинен бути частиною системи і повинен взаємодіяти з нею. Звіт повинен містити опис прийнятих інженерних рішень. У ньому повинна бути показана будова мобільного застосунку та його взаємодія з іншими частинами системи.
     

       
     3 ОПИС ВИКОНАНОЇ РОБОТИ
     
     Клієнтський мобільний додаток є ключовим компонентом екосистеми Eco-Office, створеним для оперативного керування процесами фітодизайну та моніторингу розумних вазонів. Програмний продукт надає співробітникам (від адміністраторів до технічного персоналу) спеціалізовані робочі простори для контролю за IoT-датчиками та виконання рутинних операцій. Для забезпечення кросплатформовості (одночасної підтримки Android та iOS) було обрано стек React Native + Expo у поєднанні з мовою TypeScript, що дозволило отримати єдину кодову базу із суворою типізацією. Розподіл функціоналу між різними акторами системи наочно демонструє Діаграма прецедентів (Рис. 1. Дод. Б).
     З точки зору архітектури, застосунок працює виключно як тонкий клієнт (Presentation Layer) у рамках класичної клієнт-серверної парадигми (Рис. 2. Дод. Б). Усі операції з обробки інформації та взаємодії з базою даних винесені на бекенд. Обмін даними здійснюється через RESTful API по захищеному протоколу HTTPS. Сеанси користувачів захищені механізмом JWT-аутентифікації. Повний алгоритм роботи користувача з системою зображено на Діаграмі діяльності (Рис. 3. Дод. Б). Пакетна структура проєкту (Рис. 4. Дод. Б) відображає логічний поділ на шари маршрутизації, глобального стану (Zustand), комунікації з сервером та візуальних компонентів.
     Мережева взаємодія базується на бібліотеці Axios із застосуванням патерну Interceptor. Це дало змогу централізувати процес прикріплення JWT-токенів до кожного вихідного HTTP-запиту, уникаючи дублювання коду.
     Назва інструменту ШІ: Google Gemini 1.5 Pro
     Промпт для створення коду: "Write an Axios interceptor in TypeScript for a React Native app that automatically injects a bearer token from Zustand's useAuthStore into the Authorization header."
     Внесок автора: Було імплементовано додаткову логіку перехоплення помилки 401 (Unauthorized) для примусового завершення сесії користувача у разі закінчення терміну дії токена.
      1. export const apiClient = axios.create({
      2.     baseURL: 'https://api.eco-office.com',
      3. });
      4. 
      5. apiClient.interceptors.request.use((config) => {
      6.     const currentToken = useAuthStore.getState().token;
      7.     if (currentToken) {
      8.        config.headers.Authorization = `Bearer ${currentToken}`;
      9.    }
      10.    return config;
      11. });
     Для безперервного отримання телеметрії з датчиків впроваджено бібліотеку TanStack Query. Замість встановлення постійного WebSocket-з'єднання використано оптимізований механізм Polling, який періодично опитує сервер лише тоді, коли відкрито екран моніторингу конкретної рослини.
     Назва інструменту ШІ: Google Gemini 1.5 Pro
     Промпт для створення коду: "How to implement background API polling using useQuery in React Native, ensuring it only runs when a specific target ID is selected?"
     Внесок автора: Додано параметризацію запитів через унікальні ключі (queryKey) та інтегровано умовне виконання (enabled), що значно зменшило навантаження на мережу та зберегло заряд батареї мобільного пристрою.
      1. const { data: iotReadings, isLoading } = useQuery({
      2.     queryKey: ['sensorData', activePlantId],
      3.     queryFn: () => apiService.fetchReadings(activePlantId!),
      4.     enabled: Boolean(activePlantId),
      5.     refetchInterval: 5000, 
      6. });
     Візуальна складова побудована за допомогою UI-фреймворку React Native Paper. Для безпечної та зручної роботи з формами інтегровано пакет react-hook-form разом із валідатором Zod, що забезпечує миттєву перевірку введених даних (наприклад, формату email чи довжини пароля) на стороні клієнта.
     Назва інструменту ШІ: Google Gemini 1.5 Pro
     Промпт для створення коду: "Build a React Native Paper login form controlled by react-hook-form and validated with Zod. Show error texts dynamically under the inputs."
     Внесок автора: Компоненти були стилізовані відповідно до UI/UX концепції еко-офісу, також інтегровано обробку асинхронних станів завантаження та виклики методів глобального стору Zustand.
     Маршрутизація екранів реалізована через react-navigation. Інтерфейс додатку є повністю динамічним: після авторизації система аналізує поле role з даних користувача і рендерить виключно ті вкладки (Bottom Tabs), які відповідають його посаді (наприклад, лише вкладку завдань для прибиральника).
     Назва інструменту ШІ: Google Gemini 1.5 Pro
     Промпт для створення коду: "Design a root navigator in React Native using @react-navigation/native-stack. Render different BottomTabNavigators conditionally based on the user's role stored in a global state."
     Внесок автора: Розроблено безпечну систему fallback-маршрутів: якщо токен пошкоджено або сервер повертає невідому роль, навігатор автоматично виконує логаут та повертає користувача на стартовий екран.
     Застосування методів штучного інтелекту під час розробки
     У процесі проєктування та написання коду як інтелектуальний асистент активно використовувалася мовна модель Google Gemini 1.5 Pro. Основною метою її залучення була генерація базового boilerplate-коду (типізація DTO-інтерфейсів, налаштування навігаційних стеків, написання базових хуків).
     Особистий внесок розробника: Згенеровані нейромережею фрагменти коду пройшли ретельний аудит та ручний рефакторинг. Зокрема, було власноруч розроблено логіку "розумного" парсингу вкладених JSON-об'єктів для коректного відображення некоректно сформованих IoT-даних від бекенду. Також було оптимізовано параметри JavaScript-рушія Hermes для Release-збірок, створено унікальний UI-дизайн компонентів та налаштовано процеси CI/CD через інструментарій EAS Build для генерування кінцевих бінарних файлів додатку.

     4 ВИСНОВКИ
       
     У результаті виконання лабораторної роботи було успішно спроєктовано та розроблено клієнтську частину програмно-апаратного комплексу Eco-Office у вигляді кросплатформного мобільного застосунку. Використання фреймворку React Native у поєднанні з мовою TypeScript дозволило створити надійну та масштабовану кодову базу, придатну для одночасної компіляції під операційні системи iOS та Android.
     Побудова архітектури: Успішно імплементовано клієнт-серверну взаємодію з чітким поділом відповідальності між шарами мережевих запитів, кешування та візуального представлення (UI).
     Безпека та авторизація: Налаштовано захищений обмін даними через REST API із застосуванням патерну Axios Interceptor для автоматичної ін'єкції JWT-токенів та обробки сесій користувачів за допомогою глобального стору Zustand.
     Робота з IoT-даними: Впроваджено механізм оптимізованого фонового опитування (polling) через бібліотеку TanStack Query, що забезпечує відображення телеметрії з датчиків у режимі реального часу без надмірного навантаження на мережу.
     Динамічна навігація: Створено гнучку систему рольової маршрутизації (React Navigation), яка автоматично адаптує інтерфейс та функціонал додатку відповідно до посади авторизованого працівника (Офіс-менеджер, Флорист, Прибиральник).
